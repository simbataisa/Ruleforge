## Key Decisions Made

- No DB migration — `auth_config` JSONB absorbs `OAuth2ClientCredentials` without schema change
- Redis token cache: key `tenant:{orgId}:webhook:{webhookId}:oauth_token`, TTL = `expires_in - 60s`, `SET NX PX` atomicity (ADR-010)
- `WebhookAuthException` signals auth failures → `AUTH_FAILURE` status (permanent, no retry, no circuit breaker)
- `OAuth2ClientCredentialsInjector` uses overloaded `injectAuth(headers, config, payload, orgId, webhookId)` for Redis key context; all other injectors unchanged
- `tokenUrl` SSRF guard applied at both API layer and injector layer (defence in depth)
- `clientSecret`, `headerValue` masked as `[REDACTED]` in all GET responses

## Risks / Watch-outs

- Rolling deploy risk: adding `OAuth2ClientCredentials` to the sealed interface requires both old and new event-service instances to be able to deserialize OAUTH2 webhooks. If a webhook is created on a new instance and an old instance then tries to deliver it, Jackson will fail. **Roll forward only** (no mixed version deployment).
- `WebhookDispatcher` dispatch branch for OAuth2 (overloaded method) must be wired before Stories 022/023 are used in production — Story 025 tests validate this path.
